# P5 notes: contracts and tokens (v0.5)

For the lead to fold into the shared files (CHANGELOG.md, SECURITY.md, docs/usage.md,
PLAN.md). Nothing here changes the package version.

## Proposed CHANGELOG lines (0.5.0)

### Added
- Component contracts for 12 components in `contracts/components/` (button, text field and validation, select/combobox, dialog, menu, tabs, tooltip/popover, accordion/disclosure, toast/alert, table with sort and filter, pagination, navigation): purpose, when not to use, states matrix, keyboard map, ARIA pattern, responsive rules, failure cases, guidance, and the check ids that cover each requirement.
- Conformance kit `contracts/conformance/`: JSON adapter format, 85 Playwright checks (keyboard, focus management, ARIA roles and states, axe-core per component region), Markdown and JSON results, and `run.js` with exit codes 0/1/2/3 (ADR-0015).
- Reference fixture (trust L1: test fixture, not a component library) that passes every check, and a deliberately broken fixture that fails checks in every component.
- Conformance runs against Radix Primitives and React Aria Components with demo pages and adapters in `contracts/conformance/targets/`; results, including failures and kit bugs found, in `docs/evals/conformance-results.md`.
- `craft tokens build`: writes `.craft/build/tokens.css` (CSS custom properties with light/dark mappings via `[data-theme]` and `prefers-color-scheme`), `tailwind.v3.cjs`/`.mjs` (Tailwind v3 preset), and `tailwind.v4.css` (Tailwind v4 `@theme`) from `.craft/tokens.json`; deterministic output; `--out` must stay inside `.craft/` (ADR-0016).

### Changed
- `craft tokens` is no longer a planned command (exit 3); `craft tokens build` is available.
- The package now ships `contracts/` (specs, kit, fixtures; not the external demo targets) and `cli/src/tokens-build.js`.
- `references/color-and-tokens.md` no longer suggests a self-referencing Tailwind v4 `@theme` mapping; it points to `craft tokens build`.

## SECURITY.md rows

| Command / script | Reads | Writes | Spawns | Network |
|---|---|---|---|---|
| `craft tokens build` | `.craft/tokens.json` or `--tokens <file>` | `.craft/build/` (or `--out`, refused with exit 2 unless inside `.craft/`) | nothing | none |
| `node contracts/conformance/run.js` | the adapter JSON and the page it names; Playwright and axe-core from the project or the CLI's install location | nothing (stdout only) | Chromium via Playwright | `file://` and loopback only; every other request is aborted unless `--allow-network` |
| `node contracts/conformance/targets/build.js` (repo-only, not packaged) | demo `main.jsx` files and `--modules <dir>` | `contracts/conformance/targets/<lib>/build/app.js` (gitignored) | nothing (esbuild JS API in process; esbuild itself runs its native binary) | none |

No new entries in the `scripts/lint.js` child-process or network allowlists.

## docs/usage.md CLI rows

| Command | What it does | Exit codes |
|---|---|---|
| `craft tokens build [--tokens <file>] [--out <dir in .craft/>] [--json]` | Emit tokens.css, tailwind.v3.cjs/.mjs, tailwind.v4.css into `.craft/build/` | 0 written; 1 invalid tokens (schema, unresolved reference, unsafe value, name collision); 2 usage (bad subcommand, `--out` outside `.craft/`); 3 token file missing |
| `node contracts/conformance/run.js --adapter <file> [--components a,b] [--json] [--allow-network]` | Run the component conformance kit against any implementation | 0 all pass or n/a; 1 failures; 2 usage; 3 Playwright/axe-core/Chromium unavailable |

Usage: plain CSS imports `tokens.css`; Tailwind v3 imports `tokens.css` and adds `presets: [require('./.craft/build/tailwind.v3.cjs')]`; Tailwind v4 does `@import "tailwindcss"; @import "./.craft/build/tailwind.v4.css";` instead of tokens.css.
