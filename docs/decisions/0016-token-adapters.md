# ADR-0016: Token adapters (CSS variables, Tailwind v3 and v4)

- Status: accepted
- Date: 2026-10-14

## Context

`.craft/tokens.json` holds primitive, semantic, and component tokens with per-theme
values. Projects consume tokens as plain CSS, through Tailwind v3 (JS config), or through
Tailwind v4 (CSS `@theme`). craft writes only inside `.craft/`.

## Decision

- `craft tokens build` writes `.craft/build/tokens.css`, `tailwind.v3.cjs`,
  `tailwind.v3.mjs`, and `tailwind.v4.css`. The user imports or copies them.
- Names: primitives `--primitive-<group>-<name>`, semantic `--<group>-<name>`, component
  `--<component>-<name>`. Name collisions are errors.
- References become `var()` so a theme swap only redefines semantic and component tokens.
  The first theme is the default (`:root`); a theme named `dark` also applies under
  `prefers-color-scheme: dark` unless `data-theme` pins a theme; every other theme gets a
  `[data-theme="<name>"]` block.
- Tailwind v3: a preset whose `theme.extend` maps semantic groups to Tailwind keys with
  `var()` values; requires `tokens.css`.
- Tailwind v4: a self-contained stylesheet: primitives and component tokens in `:root`,
  semantic tokens in `@theme` under Tailwind namespaces (`space` -> `--spacing-*`,
  `elevation` -> `--shadow-*`, easing -> `--ease-*`), theme overrides redefine those names.
  Durations have no v4 namespace and stay in `:root`.
- Output is deterministic (token-file order, no timestamps) and carries the header
  "generated by craft tokens build; do not edit". Values containing `; { } \`, newlines,
  or comment markers are rejected.
- No palette is added. Tailwind's own defaults are left alone.

## Consequences

Primitives are not exposed as Tailwind utilities, nudging authors to semantic roles.
Tailwind v3 opacity modifiers do not work on `var()` colors. Breakpoints are emitted as
literals for `screens`/`--breakpoint-*` because media queries cannot read variables.
